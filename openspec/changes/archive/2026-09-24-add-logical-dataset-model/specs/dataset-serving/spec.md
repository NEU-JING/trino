## ADDED Requirements

### Requirement: 模型接口

系统 SHALL 提供模型接口，用于按稳定标识读取数据集的元数据，包括字段、字段语义角色、关系、版本与血缘。

#### Scenario: 列出可消费数据集

- **WHEN** 消费方请求数据集列表
- **THEN** 系统返回可消费数据集的标识、名称、描述与版本

#### Scenario: 读取数据集模型

- **WHEN** 消费方按标识请求某数据集
- **THEN** 系统返回其字段、语义角色、关系与版本信息

### Requirement: SQL 查询暴露

系统 SHALL 将数据集暴露为可 SQL 查询的对象，使消费方可通过 SQL 直接查询数据集，且查询受既有权限机制约束。

#### Scenario: 通过 SQL 查询数据集

- **WHEN** 消费方使用 SQL 查询某已发布数据集
- **THEN** 系统返回该数据集的结果集

#### Scenario: 无权限查询被拒

- **WHEN** 消费方查询其无权访问的数据集
- **THEN** 系统拒绝该查询并返回权限不足

### Requirement: 指标写回

系统 SHALL 允许消费方（如指标平台）以 AGGREGATE 数据集的形式写回指标定义，写回的数据集 MUST 与其它数据集一样受版本、治理与物化机制约束。

#### Scenario: 写回指标

- **WHEN** 指标平台提交一个 AGGREGATE 数据集定义（含度量、维度与过滤）
- **THEN** 系统创建该数据集并纳入统一的版本与治理流程

#### Scenario: 写回需鉴权

- **WHEN** 未授权的消费方尝试写回数据集
- **THEN** 系统拒绝该操作并返回权限不足

### Requirement: 用量观测

系统 SHALL 记录并对外提供数据集的用量观测，至少包含被查询次数、被哪些应用/用户消费、以及查询延迟与失败情况。

#### Scenario: 查看数据集用量

- **WHEN** 运营人员查看某数据集的用量
- **THEN** 系统展示其查询次数、消费方与性能指标

### Requirement: 契约稳定性

系统 SHALL 以稳定标识对外提供数据集，且已发布版本的模型接口输出 MUST NOT 因后续变更而破坏性改变。

#### Scenario: 稳定标识

- **WHEN** 数据集发生版本更新
- **THEN** 其稳定标识保持不变，消费方绑定不受影响
