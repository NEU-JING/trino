## Context

需要为领导演示提供「一个 SQL 跨多个办公系统查询」的真实感。当前数据仅存在于远端、不可重放，且无关联。

## Goals / Non-Goals

**Goals:**

- 数据可重放、可版本化、可重建演示环境。
- 业务域合理、跨源关联清晰、有真实感。
- 数据量足以支撑 JOIN/聚合/图表。

**Non-Goals:**

- 不追求生产级数据规模与脱敏合规。
- 不接入真实业务系统（仅构造贴近真实的样例）。

## Decisions

### D1. 业务域与数据源映射

```
 OceanBase(MySQL sim)          Greenplum(PG9.4 sim)         达梦 DM8
 ┌──────────────────┐        ┌──────────────────┐        ┌──────────────┐
 │ OA 办公域          │        │ 人力资源域         │        │ 财务域        │
 │ 员工花名册         │◀员工─▶│ 部门/职位/组织     │        │ 预算/成本中心 │
 │ 考勤/请假/出差     │        │ 薪资/绩效          │        │ 报销/发票     │
 │ 审批流            │        │ 社保/合同          │        │ 费用科目      │
 └──────────────────┘        └──────────────────┘        └──────────────┘
           共用键：employee_id / dept_id / cost_center_id / 会计期间
```

### D2. 数据量级与真实性

每域千行级、总量数千至数万行；中文姓名、跨季度日期、合理金额、少量 NULL。

### D3. seed 脚本随仓库版本化

按数据源拆分脚本，可重复执行（幂等）；凭据不入库。

## Risks / Trade-offs

- [seed 幂等性] → 提供 drop/create 与 upsert 策略，重复执行不产生脏数据。
- [数据量与演示耗时] → 合理规模，必要时对演示查询做索引/预聚合。
- [达梦类型映射] → 与 `add-dameng-connector` 的类型映射对齐，避免 seed 类型不受支持。
